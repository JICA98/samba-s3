## Current Architecture
```
Kotlin Compose UI (MainActivity, GamesScreen) → FileUtil SAF scan → PrecompilerService/GameRepository/ProgressRepository
        → JNI native-lib.cpp → runtime-loaded RPCSX .so (dlopen, ~25 dlsym)
        → rpcsx-android.cpp CompilationQueue (g_emulator_lifecycle_mutex) → PPUThread ppu_precompile/ppu_initialize2 → JITLLVM cache zip

Flavor: standard (INCLUDE_BUNDLED_TURNIP_DRIVERS=false) / playstore (true, sync via IS_PLAYSTORE_BUILD). Patch applied via build_rpcsx.sh.
```

## Risks & Mitigations (NEW_RISKS)
| Risk | Impact | Mitigation |
|---|---|---|
| Cumulative patch vs `e8ae148` reintroduces 20-file bulk → review churn | High | Keep pin intentionally at `e8ae148`; document `685e353` bulk was Samba delta, not upstream; reviewer verifies `git -C rpcsx show 685e353 --stat` vs patch. |
| Firmware VSH revert conflicts with future optional warmup | Medium | Keep warmup behind explicit setting `GeneralSettings.firmwarePpuWarmup`; default OFF; separate notification/jobId. |
| ISO probe via `iso_dev::open` needs fd → SAF fd bridging via `ParcelFileDescriptor` already used in `FileUtil.uriOpenFile`; handle `EINTR` and short reads | Medium | Wrap `AssetFileDescriptor` + `file_view_block_dev`, limit to header blocks, fallback to filename regex. |
| Persistent readiness fingerprint drift (new `ppu_settings` flag) → unnecessary invalidations | Medium | Use native `ppu_manifest_key()` export rather than duplicating logic in Kotlin; single source of truth. |
| Turnip reproducible build requires Mesa ~1GB checkout + NDK toolchain → CI time | Medium | `scripts/build-turnip-android.sh` caches Mesa tarball at pinned commit, uses prebuilt NDK 30.0.14904198, verifies SHA-256. |
| JSONL unbounded growth on long sessions | Low | 5MiB cap, append-only buffered, failure never crashes emulator, disabled by default in release. |
| Thermal throttling makes cold medians noisy | Medium | ≥3 runs median, separate cooled vs non-cooled series, capture `thermalservice` + `battery` per run. |
