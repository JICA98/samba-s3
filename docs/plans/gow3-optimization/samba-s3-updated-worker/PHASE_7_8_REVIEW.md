## Claims versus proof

1. **Phase 7 completion.** The report calls the device result “PASS (100% RESOLVED)” (`docs/benchmarks/2026-09-25-oneplus-13r-phase7-gow3.md:31`) and claims a release APK/core match (`:55-62`, `:202`). Its transcript and screenshot references (`:80-130`) are historical assertions, not a fresh readback of the current installed APK/core. `docs/performance/experiment-ledger.md:22` describes CR05 as qualified, but the producer terminal stores at `app/src/main/cpp/rpcsx/rpcs3/Emu/Cell/SPUCommonRecompiler.cpp:833-834,1163-1164` alone do not demonstrate all cancellation, failure, replacement, zero-work and shutdown interleavings. The test's terminal record is explicitly `mock_compile_job_record` (`scripts/tests/test_spu_compilation_dedup.cpp:665-743`); its mock program/state/flight guard (`:79-135`) are not the production implementation. Thus a passing harness checks a model, not equivalence of actual job identity, state, lifetime or cache feature identity. Require production-bound checks for concurrent same-key compile, different-key compile, cache-hit zero-work, cancellation, failed worker, module reload, stale job replacement, and restart. Terminal means producer closed **and** workers joined, with a correct reason and no fabricated completion while work is outstanding. Record generation, cache key, compiled feature set and job ID at each transition.

2. **Phase 8 completion.** The report calls the result “PASS (100% VERIFIED)” (`docs/benchmarks/2026-09-25-oneplus-13r-phase8-gow3.md:26-27`), referencing a release APK and core (`:51-58`) and gameplay images (`:122-125`). `docs/performance/experiment-ledger.md:23` describes CR06-RSX qualification. The native test defines its own Vulkan-like structures and pipeline context (`scripts/tests/test_vulkan_scratch_reuse.cpp:168-264,762`), and contains its own shrink (`:460`): model coverage, not direct execution of the production buffer and pipeline paths. `app/src/main/cpp/rpcsx/rpcs3/Emu/RSX/Program/ProgramStateCache.h:181-191` hashes `pipeline_properties` with `hash_struct`; demonstrate that every field relevant to equality is hashed semantically and padding/pointers do not split equal keys. A semantic mock hash does not establish the production key contract. Check equal states constructed with differing padding/address, unequal meaningful states, and hash/equality agreement on the actual types.
