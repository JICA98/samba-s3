# GOW3 OnePlus 13R: September 26 device findings

These are exploratory runs of the **installed 2026.09.25 release**, not the current source candidate. The installed APK/core bytes were not hashed during these runs, so the source revision cannot be assigned from the version label alone. The only connected target was the OnePlus 13R. No release APK was built or installed. Raw evidence and machine-readable results are local under `.git/gow3-13r-private/jobs/W14-GETLLAR-AB-20260926/` and `.git/gow3-13r-private/jobs/W15-GETLLAR-COLD-AB-20260926/`.

The effective W15 settings come from each run's `logs-a/cache-RPCSX.log` and `logs-b/cache-RPCSX.log` current core log (`SPU GETLLAR Busy Waiting Percentage: 100` and `0`, respectively). The larger `rpcsx_app.log` and `rpcsx_backend.log` copies contain retained older sessions and cannot establish this run's settings.

| Run | Effective GETLLAR busy wait | Result | Why it is unscored |
|---|---:|---|---|
| W14 A | 100% | Android killed a long-lived app process for `LOW_MEMORY` at 14:56:03 local. The final surface rate collapsed to 4–7 FPS; the core log had warned of more than 1.95 GB allocated in Vulkan memory type 0. | Process reused previous boots, scene was not controlled, and LMKD interrupted the run. |
| W15 A | 100% | Fresh process reached Gaia gameplay. A live screenshot showed about 10.9 overlay FPS and 385% SPU host CPU at thermal `SEVERE`. Two FIFO desync warnings preceded an RSX fatal at core uptime 0:05:05.84. Surface presentation stopped at counter 13397 while the SPU number remained above 300%. | The renderer died during the short gameplay window; post-fatal CPU is not work per useful frame. |
| W15 B | 0% | Another fresh process reached moving Gaia gameplay sooner. Two screenshots showed about 14.2/12.4 overlay FPS and 411/377% SPU host CPU at thermal `SEVERE`; the surface counter advanced and the game stopped cleanly. Process PSS approached 4.4 GB. | The scene, route timing, memory pressure and thermal trajectory were not matched to A. |

The W15 A fatal was `rsx::expected<texture_wrap_mode>` verification failure. Its state dump includes enabled texture 2 with `NV4097_SET_TEXTURE_ADDRESS = 0x204f2500`, whose low wrap nibble is invalid. FIFO warnings appeared before the fatal, but a causal link is not established. This failure is distinct from the isolated W09 `NV4097_GET_REPORT` bounds candidate. W15 B logged one FIFO desync warning but no core fatal before its clean stop.

The user reports a separate reproducible condition: **many enemies on screen plus Kratos using magic** causes a crash with no new frames. The previous manual run used swords only, and W15 automation sent only START; neither is a controlled reproduction of the magic condition. The large visual effect frozen in W15 A must not be labeled as Kratos magic from the available evidence. W15 A demonstrates that an RSX no-frame failure can also occur without that input.

The subsequent W17 profiler attempt is also excluded from gameplay evidence. Its first boot retained `SPU Profiler: false` from the existing process; a cold restart confirmed `true` with LLVM/Mega. The assistant then mistakenly ran `agent-device open com.zenithblue.sambas3` while preparing a screenshot, foregrounding MainActivity and interrupting emulation at about core uptime 1:37.6. The user confirmed this navigation. The built-in CPU profiler did export block samples, but they cover startup/intro and the interrupted session, not a verified gameplay window. The emulator stopped cleanly, logs were collected, the app was force-stopped, and the original config hash below was restored and verified. W17 evidence is under `.git/gow3-13r-private/jobs/W17-SPU-PROFILE-20260926/`. Future live screenshots must not open or foreground the application.

These captures confirm high host SPU accounting while the renderer is live, so the problem is not confined to CPU work after an RSX failure. They do **not** establish that GETLLAR busy waiting causes that work or that setting it to 0 improves FPS. The supplied Astra Pro research identified the duplicate successful SPU cache append; that fix is committed in core `f2c35d714` and parent `5f890db`, with ARM64 syntax validation, but it has no device FPS result. The W06 GETLLAR ceiling and ARM64 decrementer candidates remain isolated pending correctness and matched gameplay tests.

The user permits exploratory runs at thermal `SEVERE`; both runs recorded that state. A future scored run must match the checkpoint and scene, verify advancing useful frames and guest speed, measure SPU CPU time per frame, and exclude RSX death and memory-kill intervals. The original global config was restored after both experiments; its on-device SHA-256 was verified as `d034a76128c1ba873d2c6a5fdba4eaafe803e1644ae726b0d79a1ec722415bc9`. The app was left stopped. The Poco X6 Pro was absent, so the repository rule to update **both** devices after a release build prevented a new release build/install.
