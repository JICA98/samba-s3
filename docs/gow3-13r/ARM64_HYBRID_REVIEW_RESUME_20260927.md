## Initial snapshot findings

1. **P0 — LLVM fallback lacks its analysis state.** The lambda near `SPUCommonRecompiler.cpp:7900` constructs and initializes another compiler, then calls only `compile(program)`. Analysis populated the fast compiler's `m_bbs`, `m_preds`, instruction attributes and other state. LLVM compilation consumes those members, including `at32(m_bbs, baddr)` near `SPULLVMRecompiler.cpp:2134`; its new instance has no matching analysis. Unsupported entry opcodes therefore reach a broken required fallback.

   A minimal synchronous repair can transfer the existing owned analysis result immediately before fallback. Transfer `m_block_info`, `m_regmod`, `m_use_ra/rb/rc`, `m_targets`, `m_preds`, `m_entry_info`, `m_ret_info`, `m_bbs`, `m_chunks`, `m_funcs`, `m_inst_attrs`, and `m_patterns`. Keep both compiler objects private to the same SPU thread. Do not transfer `m_spurt`, LLVM context, or emission state. LLVM initializes `m_pos`, `m_size`, and `m_hash_start`; these may be indeterminate in the fast compiler. Private `m_bits` and `workload` are analyzer scratch. The next `analyse()` must reset the moved source state. Alternatively, reconstruct fully initialized owned LS, reanalyse with the fallback instance, and reject any identity mismatch; synthetic reanalysis must not invent external branch analysis.

2. **P0 — emission failure must retain the original analysis input.** Current `code.init()` and `_add()` failures call LLVM with truncated `func`, while the original analysis corresponds to `_func`. A state-transfer fix must send the original analyzed `_func` on every fallback path. The prefix and the complete program cannot be interchanged merely because they have the same entry PC.

3. **P1 — emission and allocation failure are not contained.** AsmJit instruction return values are ignored and no error handler is installed. `jit_runtime_base::_add()` (`JITASM.cpp:221`) uses `ensure` for allocation/flatten/link failures and ignores the relocation result. Its null-result check therefore does not establish a working out-of-memory fallback. Capture emission errors, check finalization and relocation, enforce code/admission limits, and abandon the fast flight before entering valid LLVM fallback. Do not publish a partial buffer. The current 512-word region cap bounds individual emission but not session-wide baseline memory.

4. **P1 — branch execution is omitted from coverage.** `fast_executed_entries` increments only when the interpreter returns `true`. Taken immediate branches return `false` after completing their architectural work (`SPUInterpreter.cpp:1579–1684`). Branch-only regions can run while reporting zero; a branch to self is mislabeled as retry. Classify the admitted branch family explicitly, count actual execution once after the opcode/state checks, and preserve branch PC. This also matters if these counters later trigger promotion.

5. **P1 — cross-core publication requires consumer synchronization.** The new baseline performs producer cache maintenance before pointer publication. The existing ARM `tr_all` loads a dispatcher slot using `ldr` and branches without consumer instruction synchronization (`SPUCommonRecompiler.cpp:278–290`). Producer `isb` alone does not implement the research's consumer protocol. The new stable selection path should acquire-load the pointer and execute the appropriate consumer synchronization before entry, with a cross-core execution test. All paths that bypass the gate require an explicit audit.

The source now uses the live entry PC, saves/restores `x21/x22` and `x29/x30`, masks sequential PC advancement, checks pending state before a helper, checks each opcode again, bounds individual regions, and retains finalized baseline code after trampoline rebuild failure. Those are meaningful corrections. They still need actual generated-code and production fallback tests. The patch uses C++ returning interpreter handlers, not the incompatible seven-argument generated handler bank.

## Minimal safe promotion architecture

1. **Align identities.** Start with the same full canonical program for both tiers. Whole-program eligibility is the simplest implementation. If a prefix baseline is retained, its promotion binding must additionally validate the complete optimized program before selection and choose baseline on mismatch. A larger LLVM artifact behind only a prefix key can incorrectly select another overlay or repeatedly re-enter failing guards. Absolute analysis coordinates also belong to the compilation input even though the existing registry deliberately shares relocatable byte-identical programs.
2. **Separate optional work from availability.** Keep `compiled` pointing at one immutable stable entry. Add a separate optimized selection and an optimization state/ticket. Queued or compiling optimization must not make callers wait when baseline code is callable. Failure, queue rejection and cancellation retain that baseline.
3. **Return unpublished LLVM output.** Factor the LLVM compile path so optional work does not mutate registry pointers, `compile_state`, dispatcher trampolines, or cache claims before validation. The coordinator validates closing state, session generation, policy, ticket and full input identity, then release-publishes the finalized entry. The old publishing `compile()` followed by a generation check is too late.
4. **Use one session-owned worker.** A registered `named_thread` under `g_fxo` can fit the actual lifecycle: `System.cpp` signals all registered threads near line 3855, joins them near 3942, destroys contexts, then calls `g_fxo->reset()` near 4360 and `jit_runtime::finalize()` near 4369. The worker must be registered before accepting jobs, reject work after close, discard queued work, and join before registry or executable storage is reclaimed. Serialize final publication and closing under one coordinator lock. A generation check outside that lock leaves a check/publish race.
5. **Own input and code through that boundary.** Jobs contain owned immutable program data and policy plus a stable ticket; no live LS pointer or detached thread. The ordinary SPU LLVM compiler uses `MemoryManager2`, whose code/data allocations belong to `jit_runtime`, and can retain artifacts until session quiescence. Do not generalize this to `MemoryManager1`, whose destructor releases its arena. Keep compiler contexts private to the worker and preserve all metadata lifetimes needed by execution/profiling.
6. **Bound admission.** Set queue count and byte limits, one active optimizer, baseline executable-byte limits, and limits on optional compiled/retired artifacts. Queue refusal must undo only the matching queued ticket without blocking the SPU. Hotness admission should stop once optimized, failed beyond the retry budget, or closing. Measure the extra shared-counter/helper work before claiming efficiency.

This design deliberately reuses the existing shutdown/join boundary and compiler backend. It does not require ORC, immediate code reclamation, or a rewritten SPU scheduler. An exact implementation still requires a new frozen-patch review.

## Runtime diagnostics fixture constraints

A plain stack or heap `spu_thread` is not a safe shortcut. Its constructor increments `cpu_thread::g_threads_created`; the balancing deletion counter is updated by the real CPU thread loop's TLS cleanup, not its destructor. This distorts accounting used by state capture. Correction to an earlier review message: session cleanup checks the registered active-thread counter, not this created/deleted difference, so the imbalance alone does not establish a shutdown exception. Its normal `cleanup()` also assumes a `named_thread<spu_thread>`, a VM allocation, a reserved raw-SPU ID and a range lock. Independently freeing the object would leave lifecycle state inconsistent.

Use a dedicated registered raw-SPU fixture created with the existing ID reservation, `idm::make_ptr<named_thread<spu_thread>>`, VM allocation and mirrored-LS mapping sequence in `kernel/cellos/src/sys_spu.cpp`. Run any diagnostic callback on that thread, under its real CPU TLS and normal exit/cleanup path. Admit it only at a serialized initialized-core boundary before guest execution, and finish/join it before gameplay or teardown. Use its own LS and registers. `g_tail_escape` reloads LS from the thread object, so an external scratch LS paired with another thread is also invalid. The factory/analyzer/compiler and returning interpreter adapter must remain the production implementations.

The existing standalone SPU ELF boot path is a smaller available route: `System.cpp` recognizes SPU ELF, initializes the runtime and calls `spu_load_exec()` in `RawSPUThread.cpp`, which already creates a legitimate `test_spu`, maps its LS, sets its entry PC and participates in ordinary lifecycle. The tester can supply this ELF. A bootstrap may load randomized test registers and an indirect target from LS before branching to the admitted region. A direct constant branch can let LLVM analysis absorb the test region into bootstrap fallback; actual executed-tier counters are essential. A bounded diagnostic snapshot on an agreed raw-SPU stop can expose output registers/LS. A self-branch still needs a bounded diagnostic execution hook or a separately classified cancellation test; timeout is not semantic success.

The current standalone loader leaves the CPU stop flag set while setting raw status to RUNNING. `Emulator::Run()` only clears the PPU stop flag, `Resume()` only clears global pause, and raw RunCntl's `try_start()` skips an already-RUNNING status. A diagnostic-owned start action is therefore required; merely booting and resuming this ELF does not prove execution. A self-checking fixture can report distinct pass/fail STOP codes through existing SPU trace logging, which is another clean observation route for a limited case set. It still requires tier execution telemetry and must leave trace logging disabled during timing runs.

## Promotion integration audit in progress

Using full `spu_item.data` with a separate prefix emission plan and an immutable selector is a viable direction. The ordinary LLVM `compile()` cannot be reused unchanged for optional promotion. It claims `compiled_fast -> compiling_optimized` near `SPULLVMRecompiler.cpp:1530`, then stores a replacement `compiled` pointer and rebuilds dispatch near line 2945 before a worker could validate its final publication. `find()` and `rebuild_ubertrampoline()` consume that pointer without consulting `compile_state`. On trampoline rebuild failure, the current LLVM path clears `compiled`, while its guard restores `compiled_fast`, losing the callable baseline. Optional compilation therefore needs an unpublished result path that bypasses shared availability state, registry publication and optional cache claims until the coordinator accepts the result.

The existing worker lifetime can be reused with care: `spu_llvm::operator()` retains a local owning worker-group pointer, aborts workers on exit, and group destruction joins every named thread. This is source support for the session join approach, not proof of a proposed implementation. Add bounded ARM admission and serialize close against final pointer publication. The worker must reinitialize per job, fully clear its synthetic LS (the legacy clear omits one word), and reject reanalysis identity mismatch including absolute input coordinates; `spu_program::operator==` deliberately ignores absolute relocation.

The optimized selector must guard all optimized input, including bytes before entry when `lower_bound < entry_point`. Existing dispatch comparisons use only the suffix from entry. Compute the live lower bound from the entry offset, reject underflow/overflow, and select baseline directly when any required optimized byte differs. Otherwise an optimized guard can reject an earlier byte and redispatch into the same suffix-matching selector indefinitely.

The same coordinate distinction exposes a synchronous fallback race to address in the LLVM refactor. `take_analysis_state_from()` validates the caller's absolute entry/lower coordinates, but ordinary LLVM compilation then uses `add_loc->data`, which may belong to the first caller at a different address because registry equality is relocation-normalized. After a fast-emission failure abandons its flight, a relocated waiter can win LLVM ownership with analysis at one address and canonical item data at another. Preserve the actual analyzed input coordinates for LLVM emission, even when registry identity is shared. A local input copy only when coordinates differ is one small implementation option. Do not independently rebase the many analyzer maps. The combined relocated/same-key/failure test is necessary; the M5 bounded-test approval does not establish this race is correct.
