# W00 metric source map — read-only audit

This is the completed Luna High performance analyst's source-linked handoff for the checked-out dirty source. It is a metric provenance audit, not a target-device trace or a complete launch/save/settings map. No GOW3 gameplay timing, route, thermal, resolution or power capture was found; no scene bottleneck can be ranked from these files.

| Stage | Checked-out source | What the current path establishes |
|---|---|---|
| Native FPS/history | [`s3_perf::on_frame_presented`](../../app/src/main/cpp/native-lib.cpp#L462) counts callback events and estimates FPS from retained timestamps over about one second; it suppresses events closer than 800 µs. | A callback rate, with no unique guest frame, render frame or present ID. FPS history is capped at 60 samples and frame intervals at 240; it is not a scored per-frame run export. |
| Presentation hooks | [`native-lib.cpp`](../../app/src/main/cpp/native-lib.cpp#L505) calls the counter from Vulkan present and [surface queue hooks](../../app/src/main/cpp/native-lib.cpp#L540) also call it. | Labels `vk_present` and `surface` describe host presentation activity. They do not prove that a new useful guest game frame was produced. |
| Guest-flip hook candidate | [`emu_flip` callback](../../app/src/main/cpp/native-lib.cpp#L1600) is defined in the JNI bridge. Core `RSX thread::handle_emu_flip` and Vulkan `info.emu_flip` paths exist. | The analyst found no checked-out-core callsite that connects this callback to the JNI counter. The path and semantics require exact-core tracing before it becomes a frame source. |
| Core metric selection | [`native-lib.cpp`](../../app/src/main/cpp/native-lib.cpp#L1628) prefers an optional `_rpcsx_getPerfMetricsJson` export and otherwise uses fallback metrics. | No matching JSON export definition was found in the checked-out core source. Actual loaded-core behavior remains unverified. |
| Kotlin polling | [`RPCSX.kt`](../../app/src/main/java/com/zenithblue/sambas3/RPCSX.kt#L131) exposes JSON/fallback calls; [`PerformanceMetricsBridge.kt`](../../app/src/main/java/com/zenithblue/sambas3/monitoring/PerformanceMetricsBridge.kt#L21) merges their snapshots. | Poll intervals are clamped to 250–1000 ms. These snapshots cannot supply individual frame-time percentiles. |
| Parsing and fallback | [`PerformanceMetricsParser.kt`](../../app/src/main/java/com/zenithblue/sambas3/monitoring/PerformanceMetricsParser.kt#L15) accepts `emu_flip`, `surface` and `vk_present` labels as trusted; [`PerformanceMetricsMerger.kt`](../../app/src/main/java/com/zenithblue/sambas3/monitoring/PerformanceMetricsMerger.kt#L16) fills missing core timing from fallback. | Label and freshness checks do not establish a distinct game render or exclude duplicate/interpolated presentations. |
| Overlay | [`MonitoringRepository.kt`](../../app/src/main/java/com/zenithblue/sambas3/monitoring/MonitoringRepository.kt#L66) collects snapshots; [`MonitoringOverlay.kt`](../../app/src/main/java/com/zenithblue/sambas3/ui/monitoring/MonitoringOverlay.kt#L148) shows them. Its [preview](../../app/src/main/java/com/zenithblue/sambas3/ui/monitoring/MonitoringOverlay.kt#L82) contains hard-coded 59.7 FPS. | Preview data is illustrative. A production overlay number is still the upstream coarse callback estimate, not acceptance evidence. |
| Existing capture/scorer | [`capture-sambas3.sh`](../../scripts/perf/capture-sambas3.sh#L15) captures metadata and a short log tail, and [clears logcat](../../scripts/perf/capture-sambas3.sh#L21). [`summarize-run.py`](../../scripts/perf/summarize-run.py#L2) computes median/min/max from command-line numbers and defaults to `[100,120,110]` without arguments. | Neither script exports/validates a GOW3 per-frame run. The demo default must not be used in scoring, and pre-run log clearing would erase failure evidence. |

Smallest falsifiable W01 job: trace one verified exact-core RSX guest-flip → completed render → successful present path; assign monotonic guest/render and presentation IDs with session/process identity, then export raw frame-level timing through the existing bridge. A host evaluator must reject empty records, repeated game-frame IDs, and surface-only presentations. A fixture with 60 host presentations but fewer than 60 distinct verified game frames must never score as real 60 FPS. Passing that unit check does not establish target performance; the OnePlus 13R capture remains necessary.
