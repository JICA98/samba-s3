## Source and design findings

1. **P0, no current ARM hybrid execution.** Both fresh and restored SPU constructors choose `make_llvm_recompiler()` on ARM64 ([SPUThread.cpp](../../app/src/main/cpp/rpcsx/rpcs3/Emu/Cell/SPUThread.cpp), lines 2182–2190 and 2253–2261). `spu_fast::compile()` throws on non-x86 ([SPUCommonRecompiler.cpp](../../app/src/main/cpp/rpcsx/rpcs3/Emu/Cell/SPUCommonRecompiler.cpp), lines 7776–7792). A default-off factory switch that returns ordinary LLVM would be routing scaffolding, not the research plan's Phase 5 exit gate or a performance candidate. Require at least one actual production-dispatched ARM baseline region, effective-tier counters, and whole-region LLVM fallback before claiming a port.
2. **P0, handler ABI is not reusable as a return bank.** The archive's `handler_abi_probe.ll` only establishes a Clang 17 cross-compiled raw seven-argument GHC mapping (`x19/x20/w21/w22/x23/w24/x25`). The live `compile_interpreter()` inserts an inline `ret` explicitly called unreliable and then emits GHC tail calls; branch, channel, stop and fault paths can escape ([SPULLVMRecompiler.cpp](../../app/src/main/cpp/rpcsx/rpcs3/Emu/Cell/SPULLVMRecompiler.cpp), lines 3024–3049 and 3265–3335). Do not call `g_interpreter_table` entries from an AAPCS block stub as ordinary one-instruction functions. Use an explicit returning step/result ABI and test real generated calls with the production NDK, aliases, PC advance, stop/retry and helper paths. `spu_interpreter_rt::decode()` can supply a semantic oracle, but its current looping caller is restricted to the static decoder ([SPUInterpreter.h](../../app/src/main/cpp/rpcsx/rpcs3/Emu/Cell/SPUInterpreter.h), lines 17–38; [SPUCommonRecompiler.cpp](../../app/src/main/cpp/rpcsx/rpcs3/Emu/Cell/SPUCommonRecompiler.cpp), lines 2317–2341).
3. **P0, promotion ownership and publication need redesign before use on ARM.** The existing optimizer queues raw `spu_item*`/`spu_program*` and patches an existing entry's bytes, including an ARM branch/veneer path ([SPUCommonRecompiler.cpp](../../app/src/main/cpp/rpcsx/rpcs3/Emu/Cell/SPUCommonRecompiler.cpp), lines 7370–7550 and 7649–7739). A new baseline cannot safely assume that path handles session/load generation, LS overlays, allocation failure, immutable input, code lifetime and all readers of `compiled`/trampolines. Require an owned program snapshot, complete finalized artifact, generation and policy checks, safe entry selection, and stale-worker rejection. Keep baseline callable after optional LLVM failure. Save/load must quiesce or discard old jobs, restore canonical guest state, and rebuild/reselect code for the new generation.
4. **P1, compilation and sustained SPU work remain separate hypotheses.** Current boot path hard disables SPU precompilation ([SPUCommonRecompiler.cpp](../../app/src/main/cpp/rpcsx/rpcs3/Emu/Cell/SPUCommonRecompiler.cpp), line 767), and unseen blocks call synchronous `jit->compile()` from dispatch (line 2194). That can move compilation from loading into gameplay. A fast first tier could remove cold stalls, but a warm LLVM workload may remain limited by execution, synchronization, RSX or thermal behavior. Capture compile-attributable blocked time and SPU CPU time per verified game frame in matched cold and warm scenes before assigning the cause.
5. **P0 for FPS scoring, current overlay source is host callbacks.** `on_frame_presented()` increments the count before `vkQueuePresentKHR` or `queueBuffer` returns and deduplicates two hooks only when less than 800 µs apart ([native-lib.cpp](../../app/src/main/cpp/native-lib.cpp), lines 462–565). Kotlin accepts `surface` and `vk_present` labels as trusted overlay rates ([PerformanceMetricsParser.kt](../../app/src/main/java/com/zenithblue/sambas3/monitoring/PerformanceMetricsParser.kt), lines 15–55). The opt-in `GOW3_GUEST_PRESENT` trace links a non-skipped guest flip sequence, renderer frame ID and WSI result in the synchronous Vulkan queue path ([VKPresent.cpp](../../app/src/main/cpp/rpcsx/rpcs3/Emu/RSX/VK/VKPresent.cpp), lines 161–190, 507–509, 967–978), but it does not prove scanout, unique useful content or correct game speed. A scorer needs complete session-tagged guest/render/successful-present events, explicit gaps/duplicates and scene/speed validation. Coarse log polls cannot yield per-frame p99 or 1% low.

The archive correctly labels its A64 emitter, ABI probes and tier-state model as standalone laboratories. Its manifest states `native_arm_execution=false`, `emulator_build=false`, and `device_benchmark=false`. They are useful for implementation design and do not establish ARM SPU semantics, production publication safety or FPS benefit. The research plan's completion gate also requires both constructors, safe fallback and promotion, LS/lifecycle/save invalidation, bounded resources, x86 regression checks, and controlled cold/warm/sustained device comparisons.

| Severity | Finding and required worker action |
| --- | --- |
| P0 | After `uncompiled → compiling_fast`, ARM emission or trampoline work can throw without resetting/notifying `compile_state`; concurrent LLVM waiters can remain blocked. Add a flight guard and test failure/abort wake-up ([SPUCommonRecompiler.cpp](../../app/src/main/cpp/rpcsx/rpcs3/Emu/Cell/SPUCommonRecompiler.cpp), fast-tier `compile()`). |
| P0 | The new LLVM fallback wait loop can observe `compiling_fast → compiled_fast`, then claim `compiling_optimized` and run synchronous LLVM. That removes the intended cold first-tier benefit for a second concurrent SPU. | P0 | The eligibility check permits the last instruction at local-store PC `0x3fffc`; emitted code stores next PC `0x40000` and branches to `tr_all`, which reads outside the 256 KiB local store. | P1 | The full-code guard emits A64 `ldr w3, [x20, entry_point + i*4]` with a possible 256 KiB displacement; a W-register unsigned immediate reaches only 16,380 bytes. | P1 | Unconditional high-bit `block_hash` is not a collision-free tier marker, and advancing `block_counter` by region length before execution differs from LLVM's verification accounting. | P1 | `analyse()` commonly includes the branch or special terminator in its returned program, which the four-op whole-region whitelist rejects. The GHC entry assumptions are consistent with the current ARM gateway's `x19` thread and `x20` local-store registers; `v0/v1` are scratch vectors. The four emitted operations match the interpreter's vector semantics and load both inputs before writing the destination, covering register aliases. These source observations still require production ARM build/disassembly, direct semantic comparisons, multi-thread single-flight/failure tests, and a bounded device smoke under an exact packet. **Current decision for the in-progress diff: `NEEDS_EVIDENCE`; no pre-test approval yet.** Code and correctness are unresolved; metric validity, performance, save/load, and efficiency are unproven.

## Resumption check: missing source snapshot

The `/tmp/rpcsx-arm64-fast-tier` worktree no longer exists. Its Git branch still points to unchanged core base `39c89414bb3cd2f19f8d779437afe5f92517e968`; the prior uncommitted diff cannot be reconstructed from that branch. The only current main-core dirty change is an unrelated three-line SPU cache initialization edit. Thus the preceding snapshot review does not approve any current ARM fast-tier candidate. A fresh exact source diff, source identity, build and tests are required.

**P0 ABI constraint for the replacement candidate:** the ARM gateway enters `tr_all` through `blr x0` and later expects its link register to reach the gateway epilogue (`SPUCommonRecompiler.cpp`, ARM `g_gateway`, around lines 405–420). A fast block that calls a counter helper with `blr x16` replaces `x30` with its local return address. If it then tail-branches to `tr_all`, subsequent normal return can re-enter the fast block. The worker must remove such calls from this GHC path or prove save/restore of the link register across every call and exit in emitted A64. Generated-code disassembly and an execution test must cover the counter path. This is a source-level constraint, not a finding against a currently inspectable candidate.

The current `analyse()` appends ordinary branch and nonzero STOP/special instructions to `spu_program::data` after ending a block (`SPUCommonRecompiler.cpp`, around lines 3030–3062 and 3330–3400). A four-op whole-program whitelist will therefore reject many normal programs. Before a useful-coverage claim, require production-dispatch attempted, eligible, compiled and executed region counts with rejection reasons. **Decision remains `NEEDS_EVIDENCE`** until the replacement candidate and its exact packet are available.

**P0 handler contract for any replacement that composes existing generated handlers:** preserving `x30` around a call does not turn `g_interpreter_table` entries into one-instruction return functions. `compile_interpreter()` defines a seven-argument GHC interface with LS before thread, while the normal gateway enters with thread before LS; handlers load the next opcode and ordinarily tail-call the next handler. Its nonbranch inline `ret` is explicitly marked unreliable, and branch, channel and stop paths can escape (`SPULLVMRecompiler.cpp`, around lines 3039–3051, 3150–3167 and 3265–3335). A viable composition path requires a separate returning single-step ABI with an explicit next-PC/result status and real LLVM returns on all paths, plus a reviewed GHC-to-AAPCS adapter. Until that exists, directly emit only proven operations and send complete unsupported programs to ordinary LLVM. No current candidate containing handler composition has passed this review.
